## 四、覆盖率结果

### 4.1 总览

| Sample | 源码行 | 50% 基线 | path | size | cov_size | rare_line | 最高 | 达标 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|

| 4 | — | — | 530 | 525 | 531 | **532** | 532 | ✓ |

### 4.2 Sample 1 — 浮点数运算（80% 功能覆盖）

```
def sample1(s: str):
    number = float(s)           # line  6  ✓
    r1 = 1 - number             # line  7  ✓
    r2 = r1 / number            # line  8  ✓
    if r1 == r2:                # line  9  ✓
        sample1(str(r2 + 1))    # line 10  ✓  递归
    elif r1 < r2:               # line 11  ✓
        temp = s[...].join()    # line 12  ✓
    else:                       # line 13  —  (else 关键字不产生 trace 事件)
        temp = s[...].join()    # line 14  ✓
```

10 行中 8 行被覆盖（line 13 是 `else:` 关键字本身），三个分支全部命中。**覆盖率 ≈ 100%。**

### 4.3 Sample 2 — 字符串处理（92% 功能覆盖）

```
def sample2(s: str):
    temp = """..."""            # line 18  ✓
    r = s.split(".")            # line 19  ✓
    temp += r[1]                # line 20  ✓
    temp = temp.format(...)     # line 21  ✓
    temp = temp % len(s)        # line 22  ✓
    ...
    if can_convert_to_int(...): # line 31  ✓  (条件进入)
        math.sqrt(int(r[0]))    # line 32  ✗  (始终为 False!)
```

11 行中 10 行覆盖（line 32 未命中）。缺失原因：`can_convert_to_int(r[0])` 要求 `r[0]` 可被 `int()` 解析但 `split(".")` 结果第一段极少是纯数字字符串。**覆盖率 ≈ 92%。**

### 4.4 Sample 3 — 多级字符校验（70% 功能覆盖）

```
def sample3(s: str):
    if s[0] == 'F':                         # line 36  ✓
        if s[1] == 'D':                     # line 37  ✓
            if s[2] == 'U':                 # line 38  ✓
                t=(ord(s[4])-65)/(ord(s[3])-80)  # line 39  ✓
                if t != 0:                  # line 40  ✓
                    index = s.index("L")    # line 41  ✓
                    assert s[index+1]=='A'  # line 42  ✓  (path/size 达到)
                    if not s[...]           # line 43  ✗  (magic bytes 瓶颈)
                        raise RuntimeError  # line 44  ✗
```

7 行覆盖，line 43-44 未命中。这是灰盒 fuzzing 的典型瓶颈——需要同时满足精确字符序列 `FDU + 非P + 任意 + L + A + 非B开头`，纯随机变异成功概率极低。path 和 size 调度器均触及 line 42。**覆盖率 ≈ 70%。**

### 4.5 Sample 4 — HTML 解析（530+ 行库代码）

`sample4` 仅 3 行（构造 `HTMLParser` + 调用 `feed()`），所有调度器均 100% 覆盖自身代码。覆盖行数反映的是标准库 `html.parser` 内部代码。

## 六、调度器效果对比

| 调度器 | 优势场景 | 劣势 |
|--------|----------|------|
| **PathPowerSchedule** | 通用性最强，Sample 3 并列第一 | 无 |
| **SizeSchedule** | Sample 3 并列第一 | Sample 4 略低 |
| **CoverageSizeSchedule** | Sample 4 较高 | Sample 3 表现最差（6 行） |
| **RareLineSchedule** | Sample 4 最高（532 行） | Sample 3 中等（8 行） |

结论：没有单一最优策略，多策略互补覆盖不同盲区。
